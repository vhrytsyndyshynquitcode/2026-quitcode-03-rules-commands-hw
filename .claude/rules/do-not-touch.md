## Контекст

`app/src/core/` належить платформній команді — той самий core працює в усіх
клієнтських воркерах агенції, і зміни в ньому йдуть окремим PR через рев'ю цієї
команди. `app/scripts/`, `materials/`, `.coderabbit.yaml` і `.github/` — інфраструктура
перевірки: якщо змінити їх, перевірка почне підтверджувати саму себе.

## Правило

- Не редагуй, не створюй і не видаляй файли в:
  `app/src/core/**`, `app/scripts/**`, `materials/**`, `.coderabbit.yaml`, `.github/**`.
- Це стосується будь-якої зміни — включно з «дрібним фіксом», новим типом,
  коментарем, форматуванням і зміною імпорту.
- Не перегенеровуй `app/scripts/core.lock.json` (`npm run check:rules -- --write-lock`):
  це підганяє перевірку під зміну замість того, щоб її не робити.
- Не послаблюй `app/scripts/check-rules.mjs` і не додавай у код обхідні коментарі,
  щоб приховати порушення від перевірки.
- Читати ці файли можна й треба — заборонено лише записувати.

## Якщо задача не робиться без зміни core

Зупинись і **не редагуй** core. Замість цього напиши в чат:

1. який файл у `app/src/core/` і який експорт треба змінити або додати;
2. навіщо — яку саме задачу це розблокує;
3. який варіант у `app/src/integrations/` чи `app/src/sync/` ти розглянув і чому він не підходить.

Далі чекай підтвердження людини. Виняток «можна, якщо задача цього потребує» не існує.

## Як перевірити

- `cd app && npm run check:rules` → рядок `core-untouched` показує `0`.
- `git status --short` → жодного рядка з `app/src/core/`, `app/scripts/`,
  `materials/`, `.coderabbit.yaml`, `.github/`.
- `git diff --stat -- app/scripts/core.lock.json` → порожньо.
